# Platform shell

The shell and each authentication dialog render in isolated desktop and mobile documents. Dialogs
are locked open in these visual states, so dismissing one preview cannot change the documentation
around it. Every mobile navigation/account preview likewise uses an explicit mobile story with its
intended menu state: showcase previews remain locked open, while the collapsed anonymous preview
remains closed.

Expanded headers share one padded Agora wordmark. The compact rail uses its icon; mobile keeps the
wordmark and menu control aligned between the closed header and opened menu.

Dialog titles and fields share a leading edge. UIKit owns the header controls, fullscreen menu,
compact navigation, and action spacing. Primary actions stay separated from inputs, with service
errors grouped above submission. Mobile actions stack at full width; desktop actions keep their
natural width, with secondary actions at the end of the dialog footer. Completion states omit the footer.
Requests explain the next step before submission. Once recorded or sent, the dialog heading becomes
the outcome, with one compact status message and the submitted address below it.

Validation previews come from the same API schemas as the controllers. Invalid credentials stay
distinct from service outages, whose short heading and recovery guidance are shared across forms.
Successful login redirects. Invitation requests acknowledge list membership, with distinct warnings
for existing accounts and duplicate requests. Recovery acknowledges delivery without disclosing
whether an account exists. Controller transitions and duplicate-submission guards are covered by tests,
not interactive documentation.
