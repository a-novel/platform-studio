# Secure email links

These standalone routes intentionally omit the Studio shell. Each supported journey is documented
in isolated desktop and mobile documents.

The current outcome is the page’s only heading and its browser-tab title. Password instructions appear
only while a password is needed. Failures explain the next useful step: wait during an outage or request
a fresh link when the current one cannot be used.

Validation examples use the API package’s password schema, including both length boundaries.
Rejected, expired, and already-used links share the same error because the API does not distinguish
them. Email confirmation has no editable form; account creation logs the user in before continuing to Studio.
